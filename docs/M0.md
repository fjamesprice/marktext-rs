## Decisions the plan did not cover

### 1. Repository path

The brief said `C:\Dev\marktext-rs` and also "(the current working directory)",
which is `C:\Dev\marktest-rs` — note `marktest`, not `marktext`. The working
directory won, since that is what was actually provisioned. **If the `s` is a
typo, this is worth renaming now** rather than after a remote exists; nothing
in the repository hard-codes the directory name.

### 2. `BlockMeta` is named by §2.2 but never defined

`Edit::SetMeta { node, meta: BlockMeta }` references a type the plan does not
specify. Modelled as an enum with one variant per TypeScript state interface
that has a `meta` object — heading level, code-block kind/info/fence length,
table-cell alignment, list marker/loose/start/delimiter, task-item checked,
footnote identifier, and so on.

Blocks whose TypeScript interface has no `meta` (paragraph, thematic break,
html block, and every container except lists, task lists, task items and
footnotes) have no variant, because there is nothing to set.

The alternative — expressing a metadata change as `ReplaceBlock` — would
discard the block's text and children, and therefore its node identity, on
every heading-level change. That would be wrong for undo and wrong for
incremental layout.

### 3. `Block::name()` and `Block::is_leaf()` are implemented, not `todo!()`

The brief asked for `todo!()` bodies "where methods are implied". These two are
the exception, and deliberately so: `name()` **is** the 1:1 mapping onto muya's
`TState` union, and the mapping is the precondition for the differential
harness. Leaving it as `todo!()` would mean the constraint the brief calls
"what makes the differential harness possible" was documented but not checked.

Implemented, it is checked: `block_names_match_typescript_union_one_to_one`
compares all 19 discriminants against the transcribed TypeScript list, and
`no_link_reference_definition_variant` asserts the deprecated stub was not
resurrected. Adding a variant fails compilation until it is listed; adding a
name that muya does not have fails the test.

Everything requiring actual model implementation — `apply`, `text`, `children`,
`meta`, `highlight_language`, the arena, the dirty set — is `todo!()`.

### 4. Placeholder types for dependencies that have not landed

`Text::Rope(Rope)` in §2.1 means `ropey::Rope`, and §5 means `parley`, and so
on. The brief says not to front-load the §8/§12 dependency tables, so:

- `Text::Rope` holds a placeholder `Rope` **newtype** wrapping a `String`, not
  a type alias. An alias would make `Text::Inline` and `Text::Rope`
  structurally interchangeable and let code silently depend on that. At M2 the
  newtype body is replaced by `ropey::Rope` and the enum is untouched.
- `Arena<Node>` is hand-rolled and minimal. Whether it becomes `slotmap`,
  `id-arena`, or stays hand-written depends on whether generational indices are
  needed to catch a `NodeId` used across an undo boundary — an M2 question the
  plan leaves open by writing `Arena<Node>` without naming a crate.

### 5. `#![allow(dead_code)]` in `document.rs`

`Document`'s fields are private (as §2 writes them) and every method body is
`todo!()`, so nothing reads them and `-D warnings` fails. The allow is scoped
to that one file with a comment to remove it at M2, rather than applied
crate-wide, so genuinely dead code elsewhere still gets caught.

### 6. The CommonMark fixtures had to be generated, not copied

The largest gap found. §11.1 and §14.2 say to copy `packages/muya/test/spec/`
into `spec/` unchanged and run the ratchet against it. That works for GFM,
whose 672 fixtures are a committed JSON file. It does **not** work for
CommonMark: `commonmark.spec.ts` pulls those 652 examples from the
`commonmark-spec` **npm package** at test time.

A verbatim copy therefore yields a ratchet that checks GFM and not CommonMark —
silently halving the gate, including the 87.7 % CommonMark floor that the M2
exit criterion is stated in.

`tools/vendor-commonmark-spec.mjs` extracts the same examples into
`spec/fixtures/commonmark-spec-0.31.json`, in the shape the GFM file already
uses. The output is committed, so CI runs the ratchet without needing Node or
the marktext clone; CI separately runs `--check` so drift is caught.

Detail worth knowing: the inherited failure lists leave **two examples** of
slack above each floor (88.0 % achievable vs 87.7 % required; 86.6 % vs
86.3 %). Re-baselining at M2 has almost no room.

### 7. The ratchet has no on-switch

The brief asked to "document how to flip it on at M2". The better answer was to
make there be nothing to flip: `mt_md::render_to_static_html` returns
`Err(Unimplemented)`, the runner maps that to `Verdict::Skipped`, and the first
run where the function returns `Ok` is the first run where the ratchet
enforces. No flag to remember, no chance of shipping M2 with the gate still
off.

The same shape is used for the differential harness. `spec/README.md` documents
what does still need doing by hand on that first run: re-baselining
`expected-failures.json`, updating `conformance.md`, and deleting the test that
asserts everything is currently skipped — which fails loudly the moment the
engine starts rendering, and whose failure message points at the runbook.

### 8. Exit code 3 means "unimplemented", everywhere

`mt-cli` and `dump-ts-state.mjs` both use `0` success, `1` error, `3`
unimplemented-or-unavailable. Without the third code, "the Rust engine does not
do this yet" and "the Rust engine tried and crashed" are indistinguishable, and
the harness must either fail on both (CI red for all of M1) or skip on both
(CI green through a real regression).

### 9. The comparator is Rust, the dumper is Node

§11.2 draws two dumpers and one comparison. The TypeScript dumper has to be
Node; the comparator could be either. It is in `xtask` so that all pass/fail
logic lives in one place, is unit-tested (13 tests, including "catches a
truncated code-fence info string" and "catches a reference definition that grew
its own block type"), and runs identically on three platforms without a shell
script per OS. `dump-ts-state.mjs` stays a dumb dumper with no opinion about
agreement.

### 10. `tsx`, not Node's native TypeScript support

Node 24 strips types natively, but only *erasable* syntax.
`markdownToState.ts` uses a constructor parameter property —
`constructor(private _options: IMarkdownToStateOptions)` — which is not
erasable, so native stripping fails. `tsx` (esbuild) is a devDependency of this
repo for that reason. It is also why the dumper imports by `file://` URL: on
Windows an absolute path like `C:\…` is read by the ESM loader as a URL with
scheme `c:`.

### 11. Four contracts the two dumpers must share

Recorded in `tools/diff/README.md`, because a mismatch in any of them makes a
disagreement uninterpretable rather than informative:

1. **Options** — `MUYA_DEFAULT` and `SPEC` mirrored on both sides.
2. **Input normalisation** — strip UTF-8 BOM, CRLF → LF, because muya
   normalises to LF internally.
3. **Canonical JSON** — keys sorted recursively, array order preserved.
4. **Exit codes** — as above.

The Node dumper takes N files and emits one envelope, rather than one file per
process, because tsx startup dominates the cost for small inputs. The full
22-file corpus takes ~25 s, nearly all of it the TypeScript engine on the 1 MB
and 5 MB files.

### 12. `normalizeHtml` was ported to Rust now

The ratchet cannot compare anything without it. Ported by hand from
`spec/runner.ts` as four scanning passes rather than four regexes — no `regex`
dependency, consistent with the M0 dependency policy — with the exact JS regex
each pass replaces quoted in its doc comment, and unit tests for every
behaviour `runner.ts` documents (including the negatives: content between tags
is preserved, `<brx>` is not `<br>`, inner blank lines survive).

Two limitations are inherited deliberately rather than fixed, because fixing
them would make the two runners disagree: an attribute value containing `>`
breaks tag scanning, and the attribute pass does not lower-case tag names.

**A verification is owed at M2.** None of this can be checked end-to-end until
`render_to_static_html` produces output. When it does, the cheap
high-confidence check is differential — feed the same HTML through this
function and through the TypeScript `normalizeHtml` and assert agreement. It is
a few lines on top of the existing harness, and it is noted in
`xtask/src/html.rs` and `tools/diff/README.md`.

### 13. The §1 dependency constraint is machine-checked

> *Dependency direction is strictly downward; `mt-doc`, `mt-inline`, `mt-md`,
> and `mt-layout` never depend on `mt-ui` or `mt-app`.*

That sentence is the load-bearing architectural invariant — the conformance
ratchet, the differential harness, the round-trip property tests and the
fuzzing gate all rest on those four being runnable headlessly. It is also
exactly the kind of constraint that erodes one convenient `use` at a time, and
Cargo catches a dependency *cycle* but not a one-way edge.

`cargo xtask deps` checks: the crate list matches §1 exactly; no headless crate
declares `mt-ui` or `mt-app`; none declares a windowing, GPU, or I/O crate from
the §8 table; and none of their sources mention `std::fs`, `std::net`, or
`std::process`. Crude on purpose — a line scan over manifests we own, not a
TOML parser, because the alternative is a dependency.

Inter-crate edges were wired only where the plan states them
(`mt-md → mt-doc`, `mt-layout → mt-doc + mt-inline`, `mt-render → mt-layout`,
`mt-cli → mt-doc + mt-md`). The rest are added as they are needed; an
optimistic edge now is just a guess that has to be unpicked.

### 14. Corpus generated deterministically and committed

~6.6 MB, dominated by `5mb.md`. Committed rather than generated on demand so
that CI, benchmarks and the differential harness are hermetic. `cargo xtask
corpus --check` runs in CI, so a hand edit is caught rather than silently
becoming the new baseline. The PRNG is a hand-written xorshift, because
`rand`'s generators explicitly do not promise reproducibility across versions.

Content was chosen to exercise the constraints, not just the sizes — the fence
corpus contains four-backtick fences wrapping three-backtick runs and
multi-word info strings; the CJK corpus contains the no-space `中文**粗体**紧邻`
flanking case; the emoji corpus contains ZWJ sequences and regional-indicator
flags. Details in `bench/corpus/README.md`.

### 15. CI choices

- **The reference engine is pinned to a commit**
  (`fjamesprice/marktext@e52106fd`), not a branch, so a CI failure is always
  about this repository's change. That commit is also what
  NATIVE-REWRITE-PLAN.md §2 measured from, which makes it the natural §13 R9
  parity-freeze candidate at M2 start.
- **`--require-ts` in CI.** A missing reference engine is a hard failure there,
  not a skip. Otherwise a broken checkout step quietly reduces the differential
  harness to a no-op that still reports green — the one failure mode that would
  make the whole §11.2 investment worthless.
- **No global `RUSTFLAGS: -D warnings`.** It applies to third-party
  dependencies too, so a new lint in a future compiler becomes a CI failure in
  code this project does not own. Warnings are denied through
  `cargo clippy -- -D warnings` instead.
- **`npm install -g pnpm@10.33.4`, not `corepack enable`.** Corepack needs
  write access to the Node installation directory; it failed with `EPERM` on
  this machine and is not reliably available across the three runner images.
- **`pnpm install --filter @muyajs/core --ignore-scripts`** in the marktext
  checkout. `MarkdownToState`'s import graph reaches only `utils/marked`,
  `utils/logger` and `utils/index → dompurify`, none of which need Electron.
  ~20 s instead of 10–25 min, and it avoids the native-module rebuild that is
  the usual failure point.

### 16. Additions to `[workspace.package]`

§1's snippet gives `edition` and `rust-version` only, both used verbatim.
`version`, `license` and `repository` were added because every member needs
them; the profiles and the rest are exactly as written. The addition is flagged
in a comment in `Cargo.toml`.

`rust-toolchain.toml` pins the *channel* to `stable` rather than a version, so
CI surfaces new clippy lints as they land instead of freezing at a
known-green compiler. The floor stays `rust-version = "1.85"`.

## Nothing in the plan looked wrong

Read closely: §0, §1, §2, §3, §11, §14, plus §4, §5, §8, §9, §12 and §13 for
context. No contradictions found, and nothing was deviated from silently. The
gaps above are omissions to fill, not errors to correct.

Two observations that are not objections:

- **§0's premise holds under inspection.** `MarkdownToState.generate()` on
  ```` ```js title="x" ```` really does return
  `{ name: 'code-block', meta: { type: 'fenced', lang: 'js title="x"' }, text: 'let a=1' }`
  — the full info string preserved, inline structure unparsed. The 1:1 mapping
  the whole differential strategy rests on was verified against the running
  engine, not just against `types.ts`.
- **`meta.fenceLength` is omitted, not `null`, when the fence is three
  backticks.** So the Rust serializer must omit it too, or every ordinary code
  block will show as a `.meta.fenceLength` difference. `Option<u8>` is the
  right type; the JSON emitter must skip `None` rather than write `null`.
